# 架构

`dsh-doubt` 是 DeepSeek Harness 的 bundle 插件。它不替换 Agent，而是在现有工具循环
周围增加两个检查点。

![请求流程](../../assets/architecture.svg)

## 边界

1. **工具边界 — `tools/pre-execute`**
   在工具执行前，对危险的 live 宿主变更（写 `.dsh/profiles` / `.dsh/plugins`、进程/
   服务/注册表变更、递归删除、系统目录，以及常见的包装/编码形式）做分类。有审批通道
   时宿主可以询问；没有审批通道或策略为 `never` 时直接拒绝。

2. **回答边界 — `llm/stream`**
   插件缓冲最终回答流，抽取可执行断言（命令、路径、版本、包名、符号、实测数字、完成/
   状态断言），让一个无工具 reviewer 对照本轮真实工具调用和结果。未通过的草稿不会作为
   最终回答显示。

3. **Token 循环边界**
   内部 `doubt_review` 回执从模型工具列表中隐藏，但仍可由宿主执行。旧上下文引发的模型
   主动回执调用会被拦截：混合响应保留真实工具；只有回执的响应会停止并明确说明尚未完成
   验证。这避免了“猜回执 → `invalid` → 再猜”的循环。

## 审核结果

reviewer 可以返回：

- **approve**：可执行断言有证据支撑，放行草稿。
- **verify**：存在具体缺口或矛盾，作者获得一次有界补证机会，然后再次审核。
- **unavailable**：审核无法完成（例如 provider 故障）。草稿会 fail-open 放行并记录状态；
  审核不是正确性保证。

审核包大小受 `reviewMaxChars` 限制，长草稿会分段。每次审核记录输入/输出字符数、耗时、
结束原因、失败码和 provider 返回的 usage（如果存在）；提示词、工具原文和凭据不记录。

## 安全模型

扫描器和闸门是启发式，**不是安全边界**。它们覆盖常见 Windows/PowerShell 包装、
压缩/ACL 工具、`cmd /c`、编码 PowerShell 和本地 Node `fs` 写入，但任意代码执行或
不常见编码仍可能绕过。审核器检查证据，不检查用户意图或语义正确性。发现闸门绕过仍然
有价值，属于加固工作；报告方式见 [SECURITY.md](../../SECURITY.md)。
